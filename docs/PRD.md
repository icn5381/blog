## 2. 产品原则（决策时的最高依据）

1. **内容优先，但不等于愿景缓刑**——免费/构建期功能随上线走，有成本功能等信号
2. **博客死于断更，不死于功能少**——一切机制为"活着"服务
3. **发布一篇文章全程 ≤10 分钟**（自动化上线后）
4. **AI 件可整体删除**——删光所有 AI 功能，博客必须照常写作
5. **已知偏差**：作者会开局先开发功能，机制对此让步；唯一不豁免的是写作底线

## 4. 非功能需求

| 维度 | 要求 |
|---|---|
| 成本 | 年支出 ≤¥130（域名 ¥100 + LLM 个位数/月）；月充值 ¥10 硬上限 |
| 性能 | 纯静态 CDN 分发；零 JS 为主（Islands 例外）；375px 移动端不溢出 |
| 合规 | 域名实名；AI 内容显式标识；隐私声明随功能扩写；聊天入口提示数据流向 |
| 安全 | key 只进 Worker secret；CI secret 扫描；WAF 限流 1 条（勿用 KV 计数） |
| 可维护 | 依赖锁版本；AI 件失败不阻断构建；一键回滚；季度复盘 30 分钟 |
| 大陆访问 | 自定义域名（pages.dev/workers.dev 裸域已污染）；Vercel 备用部署热备 |

## 5. 技术架构

```
Obsidian 写作 → git push（双击 .command）→ Cloudflare Pages 构建：
  astro build 前自动跑：ai-summary.mjs（增量缓存）+ gen-llms-txt.mjs
  → 产出：静态站点 + Pagefind 索引 + rss.xml + llms.txt + sitemap
请求时动态层（聊天，未来）：functions/api/ → AI SDK v5 + deepseek-flash
  防护：WAF 限流 → Turnstile siteverify → Worker 内余额熔断
技术栈：Astro 5 + Fuwari（MIT）+ Tailwind ｜ Node ≥20 / pnpm ≥9
```

## 7. 风险与对策（Top 5）

1. **断更**（最高危）→ 季度底线 + 降级机制 + 每月三问
2. **成本失控** → 月充 ¥10 物理封顶 + 调用侧熔断 + 脚本计数 exit
3. **大陆访问劣化** → 多域名热备 + 拨测监控 + Vercel 备份
4. **第三方依赖变更**（DeepSeek 模型名/Waline 社区项目）→ 模型名环境变量化 + 评论每周 D1 导出备份
5. **AI 写作依赖** → 每月三问第二问 + 每季至少一篇纯手写

## 8. 度量（季度复盘看板）

- 内容：本季发文数（底线 6）/ 长文 vs notes 比 / 开发时长 vs 写作时长（对照《触发器诚实文》）
- 读者：RSS 订阅趋势、AI 引荐流量（CF Analytics）、来信数
- 健康度：季度三问的回答
